# Сравнение игровых мастеров

`POST /api/dm` принимает существующие системный промпт и историю. Провайдер задаётся на сервере для всего экземпляра приложения. Клиент получает `{ text }`. Генератор сцен и вариации арок используют тот же маршрут.

| `DM_PROVIDER` | Модель | Серверный ключ |
| --- | --- | --- |
| `gemini` | `gemini-3.5-flash-lite` | `GEMINI_API_KEY` |
| `deepseek` | `deepseek-flash` | `DEEPSEEK_API_KEY` |
| `anthropic`, вариант по умолчанию для прежней среды | `claude-haiku-4-5-20251001` | `ANTHROPIC_API_KEY` |

## Запуск локально

1. Установите зависимости из `package-lock.json` командой `npm ci`. Для Vite используйте Node 22.12 или новее.
2. Создайте игнорируемый Git файл `.env.local` в корне. Для первого прогона задайте `DM_PROVIDER=gemini` и внесите ключ в переменную `GEMINI_API_KEY`. Переменные с префиксом `VITE_` попадают в клиентскую сборку, поэтому секреты провайдеров используйте только с именами из таблицы.
3. Запустите `node --env-file=.env.local node_modules/vite/bin/vite.js dev`. В двух прогонах используйте тестовый профиль. У аккаунта одно облачное сохранение, поэтому для сравнения подойдут разные тестовые профили или заведомо одноразовое сохранение.
4. Переключите `DM_PROVIDER=deepseek`, добавьте `DEEPSEEK_API_KEY` и перезапустите сервер. Для тестового развёртывания задайте те же имена через секреты соответствующей среды.

## Сценарий сравнения

Проверка адаптеров с имитацией ответов API: `node --test tests/dm-provider.test.ts`. Для неё не нужны ключи.

Прогонять один набор русских сцен и команд. Зафиксировать начальное состояние, ответы игрока и результаты бросков. Включить старт, свободный ввод, проверку навыка, бой, отложенное последствие раннего решения и финал. Сравнить понимание событий, качество русского текста и долю ответов, которые клиент смог обработать. Отдельно отметить 429, тайм-ауты, блокировки ответа и обрезание вывода.

В серверном событии `[dm] generation` есть провайдер, модель, назначение вызова, задержка, причина завершения и счётчики токенов, если их вернул провайдер. `input` включает кешированные входные токены, `output` включает оплачиваемые токены рассуждений, если провайдер их указывает. `cachedInput` и `thinking` уже входят в соответствующие итоги. Событие не содержит историю или сами ответы. В стоимость сессии включайте подготовку арки и повторные оплачиваемые вызовы.

До коммерческого запуска проверить серверную проверку пользователя и лимиты на расходы. Текущий маршрут проверяет Origin и размер тела, а авторизация в интерфейсе сама по себе не ограничивает вызовы маршрута. Перед расчётом маржи отдельно замерить реальный размер контекста в начале и в конце арки.
