# Сравнение игровых мастеров

В опубликованной игре подготовка арки и игровые ходы идут в Edge Function `dungeon-master`. Функция проверяет сессию Supabase и возвращает `{ text }`. Локальный Vite использует `POST /api/dm` с тем же обработчиком.

| `DM_PROVIDER` | Модель | Серверный ключ |
| --- | --- | --- |
| `gemini` (по умолчанию) | `gemini-3.5-flash-lite` | `GEMINI_API_KEY` |
| `deepseek` | `deepseek-flash` | `DEEPSEEK_API_KEY` |

## Запуск локально

1. Установите зависимости из `package-lock.json` командой `npm ci`. Для Vite используйте Node 22.12 или новее.
2. Создайте игнорируемый Git файл `.env.local` в корне. Для первого прогона задайте `DM_PROVIDER=gemini` и внесите ключ в переменную `GEMINI_API_KEY`. Переменные с префиксом `VITE_` попадают в клиентскую сборку, поэтому секреты провайдеров используйте только с именами из таблицы.
3. Запустите `node --env-file=.env.local node_modules/vite/bin/vite.js dev`. В двух прогонах используйте тестовый профиль. У аккаунта одно облачное сохранение, поэтому для сравнения подойдут разные тестовые профили или заведомо одноразовое сохранение.
4. Для сравнения с DeepSeek задайте `DM_PROVIDER=deepseek` и `DEEPSEEK_API_KEY`, затем перезапустите сервер.

## Локальный прогон «Погасшего маяка»

1. Заполните `GEMINI_API_KEY` в `.env.local`.
2. Запустите `node --env-file=.env.local node_modules/vite/bin/vite.js dev --host 127.0.0.1 --port 4175`.
3. Откройте `http://127.0.0.1:4175/?playtest=lighthouse`, выберите персонажа и короткое приключение. Этот вход доступен на локальном Vite.
4. В финале запишите число запросов, входные и выходные токены. Счётчик берёт значения из ответов Gemini. Если ответ не дошёл или метрики отсутствуют, отдельная строка указывает число таких запросов. После перезагрузки выберите того же персонажа, чтобы открыть прохождение в той же вкладке.

## Развёртывание в Lovable

1. Откройте в проекте **More → Settings → Secrets**. Добавьте `GEMINI_API_KEY` для Gemini. Для DeepSeek вместо этого задайте `DM_PROVIDER=deepseek` и `DEEPSEEK_API_KEY`.
2. Синхронизируйте обновлённый код с проектом и разверните функцию `dungeon-master`. Её статус и логи доступны в **More → Database → Manage → Edge functions**. При необходимости попросите Lovable развернуть эту функцию в чате проекта.
3. В предпросмотре войдите через Google с тестовым аккаунтом. Проверьте вступительную сцену и ответ Мастера на первый ход. После проверки опубликуйте приложение.

Ключ используется только в Edge Function. Одна настройка действует для всех устройств, которые открывают опубликованную игру.

[Lovable Secrets](https://docs.lovable.dev/features/secrets) · [Lovable Edge Functions](https://docs.lovable.dev/features/edge-functions)

## Сценарий сравнения

Проверка адаптеров с имитацией ответов API: `node --test tests/dm-provider.test.ts`. Для неё не нужны ключи.

Прогонять один набор русских сцен и команд. Зафиксировать начальное состояние, ответы игрока и результаты бросков. Включить старт, свободный ввод, проверку навыка, бой, отложенное последствие раннего решения и финал. Сравнить понимание событий, качество русского текста и долю ответов, которые клиент смог обработать. Отдельно отметить 429, тайм-ауты, блокировки ответа и обрезание вывода.

В серверном событии `[dm] generation` есть провайдер, модель, назначение вызова, задержка, причина завершения и счётчики токенов, если их вернул провайдер. `input` включает кешированные входные токены, `output` включает оплачиваемые токены рассуждений, если провайдер их указывает. `cachedInput` и `thinking` уже входят в соответствующие итоги. Событие не содержит историю или сами ответы. В стоимость сессии включайте подготовку арки и повторные оплачиваемые вызовы.

До коммерческого запуска проверить серверную проверку пользователя и лимиты на расходы. Облачная функция проверяет сессию, Origin и размер тела. Лимит расхода на пользователя отдельно пока не задан. Перед расчётом маржи отдельно замерить реальный размер контекста в начале и в конце арки.
